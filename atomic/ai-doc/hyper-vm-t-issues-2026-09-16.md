### 关于"不调用的函数竟然不做语法检查"

- 准确的机制: 模板的函数体在**定义**时会查语法, 但**凡是依赖模板参数的名字与类型** (`VM_t<IMPL>` 的成员类型、`hart_t` 成员…) 都要等**实例化**才检查; 而类模板的成员函数是**按需实例化**的 —— 没人调用就永不实例化, 于是 `regs[rd].uv`、`hart_->pc` 这类错误整片漏掉。**非模板函数/类没有这个问题。**

| --- | --- | --- |

### 2.10 ⚖ **已评估: errno 的跨平台差异属"可接受取舍"** (用户 2026-09-16 定调; 我先前"需修"的判断已降级)

- 用户原话: "**我们知道 负数值是 errno 通常就几种配置, 没什么关系的; 但 signal 的值是会影响后续执行分支的**"。
- ⇒ 记录下来的**判别标准** (这条比结论本身更有价值):

  | 类别 | 是否驱动分支 | 跨平台一致性要求 |
  | --- | --- | --- |
  | `SIG*` (`SIGILL`/`SIGSEGV`/`SIGTRAP`/`SIGTERM`/`SIGQUIT`/…) | **是** —— `zero == SIGILL` 这类比较直接决定后续执行与宿主判定 | **必须一致** ⇒ 头文件用 `rLANG_ABIREQUIRE(SIGQUIT == 3 && …)` 钉 POSIX 值是**承重保障** (不是可选项) |
  | 负 errno (`-ENOSYS`/`-EINVAL`…) | 否 (通常只作报告/日志) | **允许宿主差异** (errno 本就只有几种配置) |
  | ATOMC 自有码 (`HYPER`/`YEILD`/`TIMEDOUT`) | **是** (判定"可恢复挂起") | **必须一致** ⇒ 已用固定 hex ✓ |

- 实测 (本机 cygwin, 规程七): 宿主 `ENOSYS=88`、`EALREADY=120`, 而 musl/riscv32 为 `38`、`114` ⇒ 差异确实存在, 但**按上述标准不构成阻塞**。
- 残留提示 (不要求改, 仅在需要时一行搞定): ① `op_GATE` 的缺省 `-ENOSYS` 只是**占位实现**, 真实现可按需返回 guest 期望的固定值; ② 若某个 guest 程序**真的**用 `errno == ENOSYS` 做分支, 宿主相关数值会改变其行为 —— 那时在门实现里钉成 musl 的 `-38` 即可。
- 对照: LIMIT 侧 (`Interface/script.*`) 同样用宿主 errno; 按"不同世界不必一致"原则**不必改**。

### 2.11 🔍 `Enable(libmb_t pc)` 复核 (`e1aaa777`) —— 方向正确; 3 条观察 (均已在冒烟里做成断言)

```cpp
void Enable()           { regs_.zero.uv = 0; }
void Enable(libmb_t pc) { regs_.zero.uv = 0; pc_ = pc; }
```

**为什么这个重载是对的**: ① 与 `Enable()` 共用"清错误状态"这一道闸, 不会绕过 §2.5 的三道闸; ② `pc_` 本就属于"宿主保证的确定值" (与 `x0`/`cyc_`/`cycles_` 并列, §2.5) ⇒ **由宿主设置 `pc` 是分工内的**; ③ 宿主不必"先 `Enable()` 再手改 `pc_`" (那样会绕过闸门语义); ④ `Enable()` / `Enable(pc)` 正好对应"**接着跑**"与"**从某处开始跑**"两个动作 —— 名字自然。

**观察 1 —— 要不要重置计数器? (需定夺)** `Enable(pc)` **不清** `cyc_`/`cycles_`。
- 实测 (冒烟): 先 `cyc_ = 7; cycles_ = 100;` 再 `Enable(0x10000)` ⇒ 两者**原样保留**。
- 风险是"账目混"而非崩溃: 上一次的 `cycles_` 会累加进新程序的统计, 残留的 `cyc_` 也会在 `inner_Execv` 顶部的 `cycles_ += cyc_` 里被吞进去。
- 语义上这取决于你怎么定义 `Enable(pc)`:
  - 若是"**接续**刚才的时间片/会话" ⇒ **保留是对的** (现状);
  - 若是"**开始一个新程序**" ⇒ 应清 `cyc_` (只清本片) 或 `cyc_ = cycles_ = 0` (新会话)。
- 建议 (倾向 ①): ① 补 `cyc_ = 0;` 并保留 `cycles_` 作为 **VM 生命周期**累计 (名字支持这个读法); ② 若 `Enable(pc)` 也表示"新会话", 则两个都清。**无论选哪个, 请在注释里写明**。

**观察 2 —— 入口不校验: 传 `0` 会变成"门 0", 不是 fault** (这是门的判据的**必然推论**, 不一定是缺陷)
- 门判据是 `pc < 0x00000800 || pc >= 0xFFFFF800` ⇒ `Enable(0)` 的第一条"指令"被当成 **门 0 调用** (`op_GATE(0)`), **不报错、不取指、不需要该地址映射** (冒烟已实测);
- 其余区间都安全: `0x800-0xFFFF` (未映射但不在门窗口) ⇒ `if_CODE` 失败 ⇒ `SIGSEGV` ✅; 未 4 字节对齐 ⇒ 解释器首条即 `SIGSEGV` ✅;
- 只有 `0x000-0x7FF` 会静默变成门 —— 而这**正是**"以门调用开头的程序"这一合法用法。
- ⇒ **不建议在 `Enable` 里硬拒** (会挡掉合法用法), 但**建议在注释里写明**: "入口落在 `0x000-0x7FF` 会被当门调用; 传 `0` 不是错误, 而是门 0"。若你更想要 fail-closed, 可让 `Enable(pc)` 返回 `int` 并用 `-EINVAL` 拒非 4 字节对齐/非映像区入口 —— 但那样就与"门启动"冲突, 所以**我倾向只补注释**。

**观察 3 —— `sp` 归属**: 见 §2.5 末的 💡。`Enable(pc)` 是写 `sp = 0x10FFE0` 最自然的位置 (一行), 建议就在此兑现契约, 顺手关掉 §2.5 唯一的悬念。

**冒烟新增 3 项断言** (规程八 3 → 6 项): `Enable(entry)` 置 `pc_` 且清 `x0` / **不重置计数器** (把观察 1 钉住, 将来改了就红) / `Enable(0)` ⇒ **门 0 被调用并正常链接回 `ra`** (把观察 2 钉住)。

  - ✅ **三条待定项已由用户答复** (2026-09-16):
    1. `mm_CHKRO` = **可读** (此前第 2 条措辞"可读…可写则返回地址"是笔误);
    2. **"触发 SIGSEGV" 由调用者检查**; 这三条**不得修改 hart** —— 理由 (用户原话): "**一个外部的调试器使用这些函数读取/写入数据显然不应该修改 hart**" ⇒ 即 §下方"不写 `regs_.zero`"的契约, 已按此记录;

  - ✅ **边界语义已写进头注释** (`e1aaa777`, 535 行): "**只要地址在非法区域, 即使 `size==0` 也触发 SIGSEGV; 地址对齐由调用者检查**" ⇒ 两条都定了 (非法地址 + `size==0` 拒绝; 对齐不做要求)。
  - ⚠ **更正我先前的说法 (用户纠正)**: 我说"区间判断**必须用 64 位**" —— **过重了**。用户: "我们地址空间只有 640K…32 位足够满足"。**准确的规则是"判断必须无溢出"**, 与位宽无关:
    - **无溢出的 32 位写法 (推荐, ≤640K 下最简)**: 先界 `addr`, 再界 `size` ——
      `if (addr < base || addr >= end) return SIGSEGV;` → `if (size > end - addr) return SIGSEGV;` (减法不会回绕);
    - 反面教材: 先算 `addr + size <= end` ⇒ `addr=0x0FFFFFF0, size=0x20` 会**假通过** (回绕掩盖越界)。
    - 依据 (仓内既有约定): `atomic/README.md:14` "向 64 位平台转译执行时映射 12G 虚拟地址、只用中间 4GB, 因此不需要检查内存越界"; `atomic/README.md:17` "只有 640K ROM+RAM"; `base/bits/base.h:124` `/* DRAM: ~640KB */`。
  - **参考实现 + 用例**: `atomic/ai-doc/checks/interpreter-smoke.cc` 的**规程四** —— 用**上面的 32 位写法**, **8 项断言全过**: 区间内 ✓ / 尾部越界 ✓ / `0x0FFFFFF0+0x20` 回绕算例 ✓ / 合法地址+`size==0` ✓ / **非法地址+`size==0` ⇒ SIGSEGV** ✓ / `CHKRO` 整段 ✓ / `CHKCS` 取串+长度 ✓ / 范围内无 NUL ⇒ 拒绝 ✓。
  - 仍建议补一句 (实现者容易忘): **`CHKCS` 的扫描必须在范围/guard-page 之前停下**, 范围内找不到 NUL 时**拒绝**而不是越界读。
- ✅ **内存布局 —— 2026-09-16 最终版 (DOS 1MB 实模式图的忠实复刻)**:

  ```
  0x00000 - 0x0FFFF   不映射              (门窗口 0x000-0x7FF 在其中; 门靠 pc 拦截, 不需要取指)
  0x10000 - 0x9FFFF   程序基本映像 576K   (ROM + RAM)
  0xA0000 - 0xEFFFF   兼容 DOS 的设备区 320K; 设备不存在则"写忽略 / 读 0x55AAFF00"
  0xF0000 - 0xFFFFF   兼容 DOS 的设备只读区 64K; **写入总是 SIGSEGV**, 读出无定义;
                      **ROM 最大 64K-16 = 0xFFF0 = 65520 字节** (与 rockey-dongle 固件同尺寸) ⇒ `0xF0000` 起 **16 字节恒为 0**
  0x100000- 0x10FFFF  用户 STACK 64K; 用户 sp 初始化为 **0x10FFE0**
  ```

  - ✅ **就是 DOS 的 1MB 实模式图**: `0-64K` 系统区 (此处不映射) / `64K-640K` 用户区 = 我们的 576K 映像 / `640K-1M` **UMA**: `640K-896K` 可写设备区 + `896K-1M` ROM 区 ⇒ 逐段对应, 移植 DOSBox 的直觉一致。栈在 `1M-1M+64K`, `sp = 0x10FFE0` ⇒ **整个栈落在经典 HMA (`0x100000-0x10FFEF`) 内** ✓ (HMA 顶端 `0x10FFEF` 正是 x86 段回绕边界; `0x10FFF0-0x10FFFF` 在 A20 开启下只是普通 RAM)。
  - ✅ **ROM 尺寸与 rockey-dongle 对齐**: 最大 `64K-16 = 0xFFF0 = 65520` 字节 —— 正好是 dongle 固件的尺寸 (`ai-context.md` 里反复出现的 `固件 65520B`)。三个好处: ① 可以**直接把同一份映像放进这个区域**; ② **`0xF0000-0xF000F` 恒为 16 字节的 0** (结构性兜底, 见下); ③ ROM 末端 `0xFFFF0` 恰好是 x86 的**复位向量**位置, 味道十足。
  - ✅ **预算吻合**: 映像 576K + 栈 64K = **640K** = `base/bits/base.h:124` 的 `DRAM: ~640KB`。
  - ✅ **上一版"栈护栏丢失"的回归已修好, 而且是白拿的**: ROM 区"写必 SIGSEGV"的 DOS 语义**顺便**当了栈护栏 ⇒ `sp` 下溢到 `0xFFFFF` 立刻报错; 而栈顶之上 (`≥0x110000`) 未映射 ⇒ **栈两侧都有护栏** (规程六已断言)。
  - ✅ **哨兵 `0x55AAFF00` 的小端首字节就是 `0x00`** ⇒ 越界字符串扫描最多多读 **3 字节** (旧 `0xFEA1DEAD` 不含 0 ⇒ 会穿过整片设备区、返回 ≈320K 垃圾长度) ✓ 且 `55 AA` 是引导扇区签名。
  - ✅ **`CHKCS` 的长度上限已从"必须"降级为"防御性"** (用户 2026-09-16 给出结构性保证): ROM 最大 `64K-16` ⇒ `0xF0000` 起 **16 字节恒为 0** ⇒ 从下方进入 F 段的扫描**必在这 16 字节内终止** (规程六的**对照实验**: 先把下邻 16 字节全填成非 0, 扫描仍在 16 字节处停下)。只有"直接传 ROM 内部或栈地址"才没有 0 保证 —— 那对字符串 API 属**调用错误**。⇒ 与用户定调一致 ("需要时还是检查下长度, 不值得为它做太多妥协"): 检查是**可选**的, 两个保证 (设备区哨兵含 `0x00` + F 段前 16 字节的 0) 已覆盖现实用法。
  - ✅ 与用户定调一致 —— "需要时还是检查下长度, 不值得为它做太多妥协": 现在这个检查就是**唯一**的妥协, 且只需一次比较。
  - ✅ **意外收获: "门不可读"由映射白拿** —— 两个门窗口 (`0x000-0x7FF` 在低 64K 内; `pc >= 0xFFFFF800` 在 1MB 映射之外) **都在未映射区** ⇒ ① 作为**数据**访问一律 fault; ② 作为 **pc** 则由 VM 在取指前拦截 ⇒ 门的"可跳转执行"完全由拦截提供, **既不需要该区域可执行、也不需要取指**。⇒ **计划文档 §4.3 说"在 M 模式下无法实现只可执行、不可读, 必须走 U 模式 + PMP" —— 本设计不需要 U 模式/PMP 也做到了**, 因为窗口根本不在映射里。同一地址的双重身份 (数据 ⇒ SIGSEGV / pc ⇒ 门) 已做成断言 (规程六)。
