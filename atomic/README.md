## 用途
- atomic 是 rockey-dongle 连接真实世界的 shell, 同时它也可以以转译的方式执行 rv32im-atomic-rockey 编译的通用的程序 ...

## 运行级别
- level 0 : rockey-dongle 运行在这个级别, 只支持一个调用 dongleExecv, 绑定真实的 ukey 实例, 支持一组程序执行 ...
- level 1 : 定义一个接口或者通用的库, 给 level 2 程序调用, 不能独立运行, 占用一个调用门的位置 ...
- level 2 : 定义一个具体的可以运行的程序, 绑定一组最小的调用门 ...
- level 3 : 定义了一组绑定着相同的 ukey, 定义了完全相同的"调用门组合"的一系列程序, 程序之间可以相互进行 lpc ...

## 基本设计
- 通常的 level 0 使用 'adm@k' 的ukey, level 1/2/3 使用 'pub@k' 的对需要在 level 0 执行的程序做审核,鉴权,验证 ...
- 使用 rv32im-atomic-rockey- 作为基础指令架构, 使用64KB的页面大小(现在64K页面大小的设备越来越多, 特别是服务器上) ...
- 我们总是假定HOST系统与我们有相同的字节序(小端序), 2/4 字节数据需要对齐到 2/4 字节, 8/16即以上的数据只需要对齐到4字节边界 ...
- 向64位(amd64, aarch64...)平台转译执行时, 我们映射12G的虚拟地址, 只使用中间的4GB, 因此不需要检查内存越界 ...
- 向32位(Arm Cortex M, wasm ...)平台转译执行时, 平台基本没有 MMU/MPU, 内存访问需要权限检查, 越界检查 ...
- 设定平台单发射, 无乱序执行, RAM不可执行,TEXT/RODATA只读, 因此 FENCE.I==NOP, 不支持 ECALL/EBREAK/CSRRW/CSRRS/CSRRC/CSRRWI/CSRRSI/CSRRCI ...
- 设定平台单线程执行且RAM无缓存(应该RAM/ROM全在Cache里, 毕竟我们只有640K ROM+RAM), FENCE==NOP ...
- 我们使用 地址 FFFF'F800 - FFFF'FF00,   0000'0100 - 0000'07FF 用做调用门,  这段地址刚好可以用 r0 做基址单指令调用 ...
- 调用门在HOST端实现, 包括 libgcc, libc, libm 等系统库, 以及暴露绑定的 rockey 系统调用 ...
- 调用门的序号定义是每次编译都可能不同的, 不同编译版本之间完全没有任何兼容性, 一组完全相同的"调用门组合"的程序运行于同一个世界 ...
- 每个实例以独立进程运行以相互隔离 ...
